Manage configuration

Start by identifying which system owns the setting. Experience Workspace configuration and Edge Delivery Services configuration serve different purposes.

Choose the right configuration

  • Experience Workspace: controls the authoring experience, including libraries, permissions, editor behavior, and optional features.
  • Edge Delivery Services: controls delivery-related behavior, including the content source, preview and publish access, response headers, and CDN setup. Use the current tools at tools.aem.live with your delivery administrator.

Changing a workspace setting does not deploy JavaScript or publish content. Likewise, pushing code does not change the workspace's configuration sheets.

Understand organization and site scope

Organization-level configuration provides shared settings. Site-level settings override the organization settings for that site. Before changing an organization setting, identify every site that inherits it and check for site overrides.

  1. In the content browser, navigate to the organization root or the specific site root.
  2. Choose Org Settings or Site Settings. The direct URL pattern is https://da.live/config#/ORG/ or https://da.live/config#/ORG/SITE.
  3. Verify the organization and site in the URL before editing.
  4. Open the relevant sheet tab. Rows, columns, and accepted values depend on the feature; use its current reference rather than inventing a key.

Make a controlled change

  1. Confirm you have configuration-write permission. Ask an existing administrator if access is missing.
  2. Save a private record of the current values and the reason for the change.
  3. Change one setting or one coherent feature at a time in a practice site.
  4. Save using the configuration editor, then reopen the affected authoring view.
  5. Test with an ordinary author's account and verify that unrelated features still work.
  6. Record the result and retain the prior values for rollback.

Configuration may affect authors as soon as it is saved; do not assume there is a separate content-publish gate. Coordinate changes to permissions and inherited settings in particular.

Know where permissions belong

Workspace permission rules are defined in the organization's configuration, including rules that target individual sites. The permissions view is another interface to those same rules, not a separate policy store. Continue with permissions and access before changing configuration access.

Validate and recover

If a change has an unexpected effect, check the site override and organization value before making another edit. Restore the recorded values in the correct scope and retest. Never remove the only working administrator's configuration access as part of an experiment.
