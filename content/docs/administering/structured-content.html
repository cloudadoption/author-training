Set up structured content

Use structured content when authors need a consistent form and a developer needs predictable JSON, such as a product record or an offer. This is different from editing the block tables of a normal page.

Agree on a model and delivery contract

Define the fields, labels, required values, validation, and consumers before creating a schema. Include examples with optional fields missing. Agree with the developer on how preview and live JSON will be consumed and how protected content will be authenticated.

Experience Workspace supports a subset of JSON Schema 2020-12, not every JSON Schema feature. Read the linked schema specification before using advanced constructs.

Enable the editor for a dedicated folder

  1. Create a meaningful folder for the records, such as a products folder in a practice site.
  2. Confirm configuration-write access and author permissions for that location.
  3. In the organization configuration, add an editor.path entry mapping the full organization/site/folder path to the structured editor at https://da.live/form#.
  4. Keep the mapping narrowly scoped so normal pages continue to use their existing editor.

Create and validate a schema

  1. Open the Schema Editor and load your organization and site.
  2. Create a schema or choose an existing one to edit.
  3. Give every node an explicit type and title. Use supported constraints and closed value lists where appropriate.
  4. Validate the schema and save only after the editor accepts it.
  5. Create a test document in the mapped folder, select the schema, and fill in the generated form.

Schemas are managed through the Schema Editor even though they are stored under the site's hidden structured-content schema area. The keys metadata and section-metadata are reserved. Empty values are treated as absent and removed from the saved data, so consumers must handle missing optional properties.

Verify preview and live JSON

The structured-content delivery endpoint has separate preview and live environments. Publishing a document makes its live JSON available; saving the form alone does not publish it. Ask the developer to validate the endpoint and any required authentication for your site.

  1. Test valid records, missing optional values, and invalid required inputs.
  2. Compare the delivered JSON with the intended contract.
  3. Preview the consuming block with the record and confirm it handles empty values.
  4. Publish a test record only after review, then verify the live response independently.

Plan indexing and page metadata

A collection listing needs an indexing strategy as well as a single-record endpoint. Coordinate delivery configuration with the developer. Structured pages can also be crawled; schema fields do not replace page metadata, access control, or sitemap policy. Use the documented metadata mechanisms when pages should not appear in search results, and remember that noindex is not a security control.
