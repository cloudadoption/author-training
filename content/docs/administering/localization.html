Plan localization and multi-site

Decide how languages, regions, and sites relate before automating content movement. Translation, rollout, and Multi-Site Manager solve different problems.

Choose a localization strategy

  • Language-based: one folder per language when regional differences are limited.
  • Region-based: group languages beneath regional folders when region-specific content is central.
  • Locale-based: target language-region pairs directly, with more content copies to govern.
  • Hybrid: translate into languages, then roll content out to regional or locale destinations.

Translate changes language. Copy moves content without translation. Rollout distributes content downstream and may merge into an existing destination. Transcreation adapts intent and tone rather than translating literally. Assign a source of truth and a local reviewer for each target.

Configure the Translate app deliberately

The Translate app uses Google Translate by default without additional setup. Supported alternative connectors include Lionbridge, Smartling, and Trados; they need provider setup and credentials.

  1. Create or edit the site's hidden .da/translate sheet.
  2. Use its config tab for service and conflict behavior, and its languages tab for source, target locations, and allowed actions.
  3. Define do-not-translate rules for technical values and other content that must survive unchanged.
  4. Choose conflict handling deliberately for sync, translation, copying, and rollout. Merge aims to preserve local edits; overwrite replaces them.
  5. Test one source document and one destination before running a large project.

Review automatic preview and publish completion settings before enabling them. Store provider secrets in an appropriately restricted credential sheet, not in this guide or source control. Use the official samples as a starting point, not a ready-made production policy.

Know what Multi-Site Manager inherits

MSM shares content across base and satellite sites. A satellite page with no local copy resolves from its base at preview and publish time. Creating a local copy detaches that page. MSM does not translate inherited content.

Setup requires the appropriate Edge Delivery content provider, organization-level base/satellite relationships on an msm tab, and the desired Prepare plugin or app. Coordinate the delivery source change with your developer; changing only the menu does not establish inheritance.

Choose merge, replace, or reconnect safely

  • Merge: applies base changes while attempting to preserve satellite edits. Structural differences can still cause unexpected results.
  • Replace: discards the satellite's local content in favor of the base. Back up the current document before using it.
  • Reconnect: deletes the local copy and resumes inheritance. Confirm that losing the local version is intended.

Check all target sites and descendants in a bulk confirmation. A base-language update can reintroduce untranslated content into a localized satellite. Review affected pages after the operation and before publication.

Run a small end-to-end trial

  1. Translate or copy a practice page with a known local edit, a technical link, and protected terminology.
  2. Run the intended rollout or MSM operation on one destination.
  3. Inspect the resulting document, metadata, links, media, and language.
  4. Resolve conflicts and get a local review.
  5. Verify preview, then publish only through the agreed workflow.
