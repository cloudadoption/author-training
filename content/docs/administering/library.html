Build libraries and templates

A library gives authors a curated set of reusable content patterns. Its block documents, templates, and icon entries must match the code and content models your site actually supports.

Prepare reusable documents

  1. Inventory the deployed blocks with your developer. Start with the site's block reference, not a block name copied from another site.
  2. Create one block document per block type, typically under a library/blocks folder. Use a table with the block name in its first row and valid content rows below.
  3. Add meaningful sample content and descriptions so authors can choose the right pattern.
  4. Create template documents, typically under library/templates, with the complete starting structure: sections, required blocks, section metadata, and page metadata.
  5. Test inserting each example into a practice page before listing it for authors.

Create the library sheets

  • Blocks: the blocks sheet uses name and path columns to point to the source block documents.
  • Templates: the templates sheet uses key and value to name and locate each template document.
  • Icons: list the supported icon tokens, labels, and icon resource links using Adobe's library format.
  • Placeholders: include your project's placeholder sheet when the site uses that feature.

Use the documented content.da.live document URLs for the library entries and confirm authors can read them. In the site configuration, add a library tab that references the relevant sheets. Use the official reference for the exact columns; blocks and templates do not use identical sheet formats.

Distinguish visual and content variants

A visual variant is encoded in the block table heading, such as a variant name in parentheses, and becomes a CSS class. A content variant is distinguished by a document heading before the table and does not add a styling class. Neither creates missing JavaScript or CSS: the deployed implementation must support the result.

Where a copied pattern must include surrounding content, the library supports container start and end marker blocks. Use these deliberately and test the full inserted structure; do not add them to ordinary content unless needed.

Offer supported metadata options

Library options can provide fields and allowed values for page and section metadata. Match each option's key to its target block, and offer only values that the site's code recognizes. Labels can be friendly without changing the saved value.

The Page tools panel uses the configured metadata options when present. Without them, Title and Description are available as text fields. Check the options sheet when an expected field or choice is missing.

Validate as an author

  1. Confirm the author can read the relevant site configuration and library sources.
  2. Open a practice document in Content mode and insert each block or template.
  3. Check rows, cells, sections, placeholder text, and required metadata.
  4. Preview the document at narrow and wide screen sizes.
  5. Remove unsupported examples and update the reference when code or models change.

This training site supplies example content and block code; it does not automatically register a workspace library.
