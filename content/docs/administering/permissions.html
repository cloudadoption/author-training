Manage permissions and access

Give people the access their role needs, then test what they can actually do. Source editing, configuration changes, previewing, publishing, and viewing delivered content are separate concerns.

Separate workspace and delivery permissions

  • Workspace permissions: govern source documents, folders, resources, and configuration through Adobe Identity Management Services (IMS).
  • Edge Delivery permissions: govern preview, publish, and access to delivered content. Manage author roles with the AEM User Admin tool and the delivery configuration tools.

Workspace write access does not automatically grant publish access. Protecting source content does not automatically protect an aem.page preview or a live URL. Verify both systems when content must be restricted.

Use the permissions view

  1. Open Org Settings or Site Settings in the content browser and select Permissions.
  2. Check the site switcher and filter. A site view can show permissions inherited from its organization.
  3. Review configuration, content, and folder permissions separately.
  4. Add the approved identity under the appropriate Read or Write group, or add a folder rule for a limited path.
  5. Verify the saved result before moving to another rule. Removing an entry with its X control saves automatically.

The permissions view and the organization's permissions sheet edit the same data. The last save wins: coordinate with other administrators rather than editing both interfaces at once. Change inherited rules at their organization source.

Understand actions, identities, and paths

  • Read allows viewing. Write includes reading, creating, editing, and deleting. It is not a harmless edit-only permission.
  • Rules can name IMS organizations, IMS groups, or individual identities. Prefer managed groups where practical and confirm the user's selected IMS organization.
  • CONFIG governs organization configuration access; a site-specific /SITE/CONFIG rule can govern its configuration. Keep a working administrator's access.
  • /SITE/folder/** matches descendants but not the folder itself. /SITE/folder/+** also includes that folder.
  • Effective actions combine matches across the user's identities and groups. An empty action in one matching group does not necessarily remove a grant from another.

Authors need appropriate configuration-read access to use the block library; they do not need configuration-write access for that task. Avoid granting broad write access to solve a library visibility problem.

Test the effective result

  1. Use a representative non-admin account to browse the intended folder and open a document.
  2. Verify expected read, edit, and delete behavior on an isolated practice document.
  3. Check configuration access separately from source access.
  4. Test preview and publish with the intended Edge Delivery roles, not just the workspace rules.
  5. If group membership changed, sign out and back in to refresh it, then retest.

A 404 can mean missing content or insufficient access. Check path rules, folder access, and the selected IMS organization before creating duplicate content. Denied documents may still have names visible in a parent list; a preview URL is not a secrecy mechanism.

If an administrator is locked out

Stop changing rules and contact your Adobe support channel with the organization, site, and last known change. Do not widen access indiscriminately or put private configuration details into a public issue.
