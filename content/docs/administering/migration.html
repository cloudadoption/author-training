Migrate and recover content

Treat imports and restores as content changes that need scope, backups, QA, and an owner. Importing a rendered page is not the same as recovering every source detail or historical version.

Inventory before importing

  • List the source pages, sheets, fragments, media, and redirects, plus the content that is intentionally excluded.
  • Confirm permission to copy the source material and write to the destination organization and site.
  • Record current destination content and configuration before any overwrite.
  • Choose a practice site or drafts destination and define how links and media should be handled.
  • Agree on a content freeze or a later delta import so edits made during migration are not lost.

Run a limited import

  1. Open the Import app.
  2. Choose a public query index or a list of public source URLs.
  3. Review linked-content behavior and the production-domain setting.
  4. Check the destination organization, site, and practice path. Importing can overwrite existing content.
  5. Import a small representative set and review success, redirect, error, and remaining counts.

Do not bypass protection by exposing private source content just to make an import work. Ask Adobe or your developer about an authorized approach for protected sources.

Restore from a preview or live site

When source content is missing but rendered preview or live pages remain, use an authorized AEM status job to obtain the intended resource list, then import those URLs into a safe destination.

Choose preview or live deliberately: they can contain different versions. Have a developer retrieve and filter the job results without sharing admin tokens. Redirects, media, and sheets need separate attention; do not assume each returned resource is an importable page.

Validate more than the page count

  1. Inspect headings, lists, links, block tables, sections, and metadata in the imported source.
  2. Preview representative pages and compare them with the original at multiple screen sizes.
  3. Check media, fragments, forms, search or index consumers, and redirects.
  4. Verify permissions, titles, canonical URLs, crawl rules, and sitemap coverage with the responsible teams.
  5. Resolve new migration defects separately from issues already present on the source site.

Plan an upgrade and cutover

For a SharePoint- or Google Drive-based site moving to Experience Workspace, plan a parallel project, representative smoke tests, full content QA, SEO checks, a final delta import, and an explicit rollback decision.

Coordinate a content-source switch or a CDN-origin switch with your developer and operations team. Manage this repository's delivery configuration through the current tools at tools.aem.live; do not add retired configuration files to follow historical examples. A source change can affect more than one code branch, so verify its scope before applying it.

Keep editor transitions deliberate

Adobe recommends Experience Workspace for new projects. Existing Universal Editor projects do not need an immediate change, and their instrumentation and extensions need a compatibility review before a transition. Follow Adobe's current setup guide rather than treating an editor-path change as a complete migration.
