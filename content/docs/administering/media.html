Connect media and services

Choose the right asset source and verify how it is delivered. Media Library, AEM Assets, focal-point authoring, and Adobe Target are separate capabilities with different setup requirements.

Use Media Library for visibility and reuse

Open the Media Library app and choose a site or supply its AEM URL. It surfaces site media, references, and metadata from a history-based index.

  1. Let the site's initial index load. Older content may need a bulk index arranged with Adobe.
  2. Filter by media type or search by name and path. Use doc: to inspect a document's references or folder: to narrow a folder.
  3. Inspect reference and metadata details before reusing or changing an asset.
  4. If authors need insertion from the editor, add the documented Media Library plugin entry to the site's library configuration.

Incomplete results can reflect permissions or indexing, not an unused asset. Check access to the site's media-insights area and the required Edge Delivery role. Do not delete media solely because an incomplete index shows no references.

Plan AEM Assets integration with its owner

The integration requires AEM as a Cloud Service with a publish instance or Dynamic Media, permission to change Cloud Manager settings, and workspace configuration access.

  1. Coordinate the Cloud Manager client configuration with the AEM administrator. Saving the required environment variable can trigger a full environment restart, so use a planned change window.
  2. Configure the site's aem.repositoryId and the appropriate asset origin, delivery, and optional rendition settings from Adobe's current reference.
  3. Check that the user's selected IMS organization can access the AEM environment.
  4. Use the asset picker to select a published test asset, then verify both authoring and delivery.

Author-only asset delivery is not sufficient. Dynamic Media modes, folder browsing, Smart Crop, and same-domain delivery have additional requirements. Do not substitute production endpoints or change CDN routing without the responsible operations team.

Enable focal points only for compatible blocks

A focal point requires two things: block code that consumes the stored coordinates and a library entry with the focal-point feature enabled. A library flag alone does not make an image crop correctly.

Ask the developer to confirm support, add the documented features value to the supported block's library row, and test an off-center subject at narrow and wide viewports. Authors can then set, accept, or clear a focal point in Content mode.

Treat Adobe Target as a separate integration

Send to Adobe Target needs a Target account and a Developer Console API integration. An authorized administrator supplies the protected tenant and credential configuration, then enables the Prepare action.

Never preview or publish the credential sheet or include secrets in guide content or Git. Restrict its access using the supported configuration mechanism and your organization's credential-handling policy.

The integration sends pages or fragments as undecorated content offers, not sheets or standalone media. Creating an offer is separate from activating an experiment and from the site's Target delivery implementation. Test the resulting offer with your personalization team.

Validate the whole delivery path

Check the selected asset's permissions, availability, metadata, alt text, responsive crop, preview rendering, and live rendering. The presence of a picker or menu item proves only that the UI is available, not that every delivery step is configured.
