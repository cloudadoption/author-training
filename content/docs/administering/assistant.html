Enable assistant workflows

Give authors useful, approved assistant capabilities without confusing a prompt with permission to act. Decide which workflows your site needs before registering connectors or adding skills.

Distinguish the moving parts

  • Prompts: reusable starting requests that authors can adapt in chat.
  • Commands: available predefined actions selected from the plus menu or slash menu.
  • Connectors and tools: integrations that expose the operations the assistant can call.
  • Skills: instructions that guide how the assistant uses those tools for a task.

Making a prompt available does not enable its underlying integration. A skill does not grant broader identity or configuration permissions. Start with the author's assistant-panel lesson to understand the interface you are supporting.

Check availability and governance

  1. Confirm the assistant is enabled for the organization and site. If its panel and show control are absent, check the administrator settings rather than asking authors to work around them.
  2. Agree on approved data sources, attachment rules, and which actions require review.
  3. Choose a limited practice site and representative author and approver roles.
  4. Document which capabilities are enabled so training prompts do not promise unavailable features.

Register AEM agentic plugins when needed

The Adobe-hosted AEM agentic plugins connector supports workflows including publish requests, scheduling, and permissions. Each feature needs its site skill as well as the connector; some features also need separate onboarding.

  1. Confirm configuration-write access and complete the feature's prerequisites. Request Publish, for example, needs customer onboarding and workflow configuration.
  2. Open the site's Skills Editor at https://da.live/apps/skills#/ORG/SITE.
  3. On the MCPs tab, register the documented aem-agentic-plugins connector using the current endpoint in Adobe's reference.
  4. On the Skills tab, add only the skills your site will support, and disable unnecessary tools where appropriate.
  5. Test read-only requests first, then a clearly scoped write on non-production content.

Verify identity and confirmations

The connected services receive the signed-in user's identity and authorize each operation. The assistant does not become an administrator simply because a connector is registered.

For AEM agentic plugin writes, expect a summary and an explicit confirmation for each action. Reading a schedule or listing requests does not need the same write confirmation. Check that the summary names the right page, scope, recipients, or scheduled time before approving.

Roll out with practical guidance

  • Give authors examples that match the enabled workflows and explain the expected outcome.
  • Teach the difference between a proposal in chat, a changed draft, a submitted request, and a live publication.
  • Review failed calls and authorization errors without sharing tokens or private configuration in chat.
  • Re-test after changing skills, connectors, or permissions. Do not use blanket approval as a shortcut.

Sources: Assistant panel, AEM agentic plugins, and Request Publish skill reference.
