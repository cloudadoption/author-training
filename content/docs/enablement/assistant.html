Work with the assistant panel

Use natural language to ask for help while you author. The assistant panel connects you to Adobe Coworker; available actions depend on your organization's settings, connected tools, site skills, and your permissions.

Open the panel and start a conversation

  1. Open your page in Experience Workspace. Find the assistant panel on the left of the content editor. If it is collapsed, use the assistant control in the editor menu to show it.
  2. Type a request in the chat box. Include the page or section, your goal, and anything that must stay unchanged.
  3. Press Enter or select the send arrow. You can also choose a recommended prompt to fill the chat box, then tailor it before sending.
  4. Read the response and any proposed action. If the assistant requests confirmation or access, check the scope before continuing.
  5. Refine your request with a follow-up. For example, ask for a shorter version or explain what the first response missed.

If neither the panel nor its show control is visible, the assistant may be disabled for the site or organization. Ask your site administrator; this guide does not enable it.

Give it useful context

A useful request names the task, audience, source material, constraints, and output you want. Be explicit about whether you want suggestions in chat or an actual change.

For example: "Suggest a new introduction for this page for first-time customers. Keep the product names and eligibility requirements unchanged. Give me two options under 60 words each in chat; do not edit the page."

  • Files or images: use the plus button to attach approved reference material from your computer. Explain how the attachment should be used.
  • Prompt: choose a predefined prompt from the plus menu. Filter the list or narrow it by type, then adapt it to your task.
  • Command: use the plus menu or type / in chat to see available commands. Choose from what your workspace actually offers.

Only provide material you are authorized to share under your organization's AI policy. Do not include passwords, access tokens, personal information, or confidential material that is not approved for this use.

Things to try while authoring

These are suggested requests, not a promise that every workspace has the same skills. Start with a response in chat so you can review it before changing your document.

Draft and refine copy

"Suggest three descriptive headings for this section. Use plain language and avoid claims that are not in the source. Reply in chat only."

"Propose a shorter version of this paragraph for occasional users. Preserve every date, number, and product name. Show the proposed text without applying it."

Plan a clearer page

"Suggest an outline for a getting-started page using the attached approved brief. List any missing facts as questions rather than inventing answers."

"Review this introduction for jargon and unclear instructions. Explain the issues and suggest alternatives in chat; do not modify the page."

Prepare for review

"Summarize this draft for a reviewer in five bullets. Separate factual claims that need checking from editorial suggestions. Do not publish or edit anything."

An assistant's review is not an accessibility audit, legal approval, or a replacement for checking the rendered page. Use your normal review and publishing checklist.

Use connected workflows when available

Some sites add the AEM agentic plugins connector and enable individual skills. Those sites may support the following tasks through the assistant. These integrations are not enabled by adding this lesson.

  • Publish approval: ask to submit a specific page for approval or list requests awaiting your review. The request-publish workflow must be onboarded and configured.
  • Scheduled publishing: ask to schedule a specific page, inspect its schedule, or cancel a scheduled publication. Confirm the page, date, time, and time zone before approving.
  • Permissions: ask who can edit a site or folder. Access changes require the appropriate configuration rights; authors should involve their administrator rather than request broader access casually.

The connected services act as your signed-in user and enforce your permissions. Read-only checks do not necessarily need confirmation; actions that write show a summary and require explicit confirmation. A request to publish is not proof that a page is live: check the action result and the destination URL.

Review changes before you keep them

  1. Verify names, numbers, dates, links, tone, and factual claims against approved sources. AI responses can be inaccurate.
  2. For an action, check exactly which page or folder is targeted and what will change. Decline or clarify if the scope is wrong.
  3. Before a substantial edit, create a named version using the Versions tools.
  4. After a change, inspect the document structure and rendered layout. Confirm that block tables, metadata, headings, and links still work.
  5. Preview the updated draft and follow your team's approval process before publishing. Do not treat an assistant response as approval.

You can copy an assistant response using the copy control that appears on hover. Use Clear at the top of the panel to start a fresh chat. Clearing chat is not a way to undo edits; inspect versions if you need to recover content.

If the assistant cannot complete the task

  • The response is too general: name the page, include the relevant passage or approved attachment, and ask for one specific result.
  • A command or action is missing: ask your administrator whether the required connector and site skill are enabled. Do not assume another site's commands are available here.
  • You are asked for permission: read the access request and confirm only what is needed. The assistant does not bypass your existing rights.
  • The request fails: keep the error and page path for your support team. Check the actual content or schedule before repeating a change that might already have succeeded.

Try it on a practice page

Open a non-production practice page and ask for two alternative headings in chat only. Refine one with a follow-up, check its meaning, then insert your chosen wording yourself. Preview the page and compare it with the original. Leave the live site unchanged.
